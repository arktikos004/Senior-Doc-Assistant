# 部署指南:讓家人用手機連上「看有」

> 給在 GPU 電腦(Windows)上架設本系統的團隊成員。做完之後:家人用手機打開一個固定網址、經 Cloudflare Access
> 登入就能使用;GPU 電腦重開機後服務會自己起來。
>
> 文中的網址、email 與 ID 都是範例(`app.example.com`、`parent@example.com`、全是 0 的 ID),請換成自己的。
> **真的網域、帳號 email、Cloudflare 帳號 ID、Tunnel ID 與 Token 一律不要寫回 repo**(競賽匿名規則與個資規則)。
> Cloudflare 的選單名稱會隨改版變動,以下是 2026 年 10 月的名稱。

## 0. 架構一覽

```
手機瀏覽器 ──https──▶ Cloudflare(Access 登入、WAF 限流)──Tunnel──▶ GPU 電腦
                                                              cloudflared ─▶ 網頁 127.0.0.1:8000 ─▶ Ollama 127.0.0.1:11434
```

- 家裡的路由器**不用開任何埠**:cloudflared 由內往外連到 Cloudflare。
- 網頁與 Ollama 只綁 127.0.0.1,同一個區網的其他電腦也連不到;對外唯一的入口是 Tunnel,登入交給 Access
  (本系統不自建帳號密碼)。

| 防護 | 擋什麼 | 在哪裡 |
|---|---|---|
| Cloudflare Access | 不在允許名單的人,連頁面都看不到 | 第 5 節設定 |
| WAF 限流 | 有人在短時間內狂送上傳 | 第 6 節設定 |
| CSRF token | 別的網站誘導已登入的家人送出表單(替人確認服藥表、取消提醒、更正讀值、改設定、刪除全部資料) | 程式內建 |
| 安全標頭 | 頁面被嵌進釣魚網頁、載入外部程式、瀏覽器或代理快取個資 | 程式內建 |
| 上傳檢查 | 超過 15MB、副檔名不對、檔頭與副檔名對不上的檔案 | 程式內建 |

## 1. 事前準備

- **GPU 電腦**:Windows 10/11、NVIDIA 顯卡(`gemma4:12b` 約 8GB,16GB VRAM 放得下)、設定成不會睡眠(第 7 節)。
- **Cloudflare 帳號**(免費方案即可)與**一個網域**:可以直接在 Cloudflare 買,或在別的註冊商買再把 DNS 交給 Cloudflare。
- **家人的 email 名單**:Access 允許名單用。
- **軟體**(PowerShell 執行):

```powershell
winget install --id Git.Git
winget install --id Python.Python.3.13
winget install --id Ollama.Ollama          # 需要 0.22 以上才支援 Gemma 4
winget install --id Cloudflare.cloudflared
```

## 2. 在 GPU 電腦上裝好「看有」

在 repo 資料夾開 PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
ollama pull gemma4:12b
```

- **一律用 `.venv\Scripts\python -m …`**,不要直接執行 `.venv\Scripts\` 裡的 `pip.exe`、`uvicorn.exe`:
  資料夾改過名之後,這些啟動器還記著舊路徑,會出現 `Fatal error in launcher`。還是不行就刪掉 `.venv` 重建。
- `config.yaml` 的 `model.provider` 平常用 `ollama`(全部在本機辨識);雲端備援見第 8 節。
- 先在本機試跑(不開通道):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\start-services.ps1 -NoTunnel
```

瀏覽器開 `http://127.0.0.1:8000` 應該看到首頁;開 `http://127.0.0.1:8000/healthz` 應該看到類似:

```json
{"status": "ok", "version": "…", "provider": "ollama", "models": {"local": "gemma4:12b"}, "ollama": "reachable"}
```

`/healthz` 只回報狀態、版本、模型名稱與 Ollama 連不連得上,不含路徑、主機位址或金鑰。確認後按 Ctrl+C 結束
(已經開好的 Ollama 與網頁會留在背景,第 7 節的開機工作會接手)。

## 3. 網域接上 Cloudflare

1. Cloudflare 儀表板 → **Add a domain** → 輸入網域 → 選 **Free** 方案。
2. Cloudflare 會給兩個 nameserver;到網域註冊商的管理頁,把 nameserver 換成這兩個。
3. 等網域狀態變成 **Active**(幾分鐘到一天)。

網域本來就在 Cloudflare 買的話,這一節自動完成。

## 4. 建立 Cloudflare Tunnel

```powershell
cloudflared tunnel login                     # 開瀏覽器登入 Cloudflare,選剛剛的網域
cloudflared tunnel create senior-doc         # 印出 Tunnel ID;憑證存在 %USERPROFILE%\.cloudflared\<Tunnel ID>.json
copy deploy\cloudflared\config.example.yml $env:USERPROFILE\.cloudflared\config.yml
notepad $env:USERPROFILE\.cloudflared\config.yml   # 換成自己的 Tunnel ID、使用者名稱與網址
cloudflared tunnel route dns senior-doc app.example.com
cloudflared tunnel --config $env:USERPROFILE\.cloudflared\config.yml run   # 試跑:看到 Registered tunnel connection 就通了
```

- `config.yml` 與 `<Tunnel ID>.json` **只放在 `%USERPROFILE%\.cloudflared\`,不要放進 repo**:憑證檔等於這條通道的密碼,
  拿到的人可以冒充你的 GPU 電腦。
- 範例設定只把 `app.example.com` 轉到 `http://127.0.0.1:8000`,其他主機名稱一律回 404。
- **7844 埠被擋**:cloudflared 用 **7844 埠**連 Cloudflare,預設先試 QUIC(UDP 7844)。學校與公司網路常擋 UDP,
  所以範例設定已經寫了 `protocol: http2`(改走 TCP 7844);命令列臨時測試也可以加 `--protocol http2`。
  - 紀錄一直出現 QUIC 連不上(例如 `failed to dial to edge with quic`)→ 確認設定檔有 `protocol: http2`。
  - 改成 http2 還是連不上(例如 `dial tcp …:7844: i/o timeout`)→ TCP 7844 也被擋,通道開不起來。換一個網路
    (例如手機熱點)確認,或請網管開放對外的 TCP 7844(目的地 `region1.v2.argotunnel.com`、`region2.v2.argotunnel.com`)。
- **不要用臨時通道對外展示真實資料**:`cloudflared tunnel --url http://127.0.0.1:8000` 產生的公開網址**沒有 Access**,
  拿到網址的人都進得來;只能配展示伺服器(`tools/demo_server.py`,合成資料)短暫使用,用完就關。

## 5. Cloudflare Access:只讓家人登入

1. Zero Trust 儀表板 → **Integrations → Identity providers**:加入 **One-time PIN**
   (用 email 收一次性驗證碼登入,家人不必另外註冊帳號)。
2. **Access controls → Applications → Create new application → Self-hosted and private** →
   **Add public hostname**:填 `app.example.com`,路徑留空(整個網站都要登入)。
3. **Policy**:Action 選 **Allow**;Include 選 **Emails**,一個一個填家人的 email(例如 `parent@example.com`、`child@example.com`)。
   - **不要**用 Everyone 或整個 email 網域;**不要**加 Bypass 規則(`/healthz` 也不要:監看腳本在 GPU 電腦上直接連
     127.0.0.1,不經過 Access)。
4. **Session duration**:建議 1 週到 1 個月,長輩才不必常常收驗證碼。
5. 存檔後,用手機的無痕視窗開 `https://app.example.com`:應該先出現 Cloudflare 的登入頁;不在名單上的 email 收不到驗證碼。

## 6. WAF 限流:擋住狂送上傳

Cloudflare 儀表板 → 網域 → **Security → WAF → Rate limiting rules** → **Create rule**:

| 欄位 | 設定 |
|---|---|
| 條件 | URI Path equals `/upload` |
| 計算依據 | 同一個 IP |
| 門檻(免費方案) | 免費方案的計算期間只能選 10 秒:**每 10 秒超過 3 次 → Block 10 秒** |
| 門檻(Pro 以上) | **每 1 分鐘超過 10 次 → Block 1 分鐘** |

- 一張照片辨識要半分鐘以上,正常使用碰不到這個門檻。
- 免費方案只能有 1 條限流規則,就給 `/upload`(只有 POST 會用到這個網址,不必另外比對方法)。

## 7. 開機自動啟動(工作排程器)

1. **關掉睡眠**:設定 → 系統 → 電源 → 睡眠設成「永不」;或在系統管理員 PowerShell 執行 `powercfg /change standby-timeout-ac 0`。
2. (建議)BIOS 開啟「斷電後恢復通電就開機」(名稱類似 AC Power Recovery、Restore on AC Power Loss)。
3. 在開始選單的 PowerShell 按右鍵 →「以系統管理員身分執行」,到 repo 資料夾執行:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\install-autostart.ps1
```

它會登記一個叫 `senior-doc-assistant` 的排程工作:**開機就以目前這個使用者的身分執行**(不必登入 Windows),
跑 `deploy\windows\start-services.ps1` 啟動 Ollama、網頁與通道,之後每分鐘檢查一次:

| 狀況 | 監看腳本的動作 |
|---|---|
| `/healthz` 連續 3 次沒回應 | 關掉卡住的網頁,重新啟動 |
| `/healthz` 回報 `"ollama": "unreachable"` | 重新啟動 Ollama |
| cloudflared 結束了 | 重新啟動通道 |

- 紀錄在 `logs\service\`:`watchdog.log` 是監看紀錄,`web.err.log`、`ollama.err.log`、`cloudflared.err.log` 是各服務的輸出。
  `logs\` 不會進 repo;裡面可能有文件編號與時間,不要貼到公開的地方。
- 登記失敗(例如用 Microsoft 帳戶登入的電腦不支援「不存密碼」的方式)→ 改加 `-StorePassword`,輸入一次 Windows 密碼。
- 移除排程工作:同一行指令最後加 `-Remove`。
- Ollama 安裝後會在登入時自動開系統匣程式。若紀錄出現兩份 Ollama 搶同一個埠(`address already in use`),
  到「設定 → 應用程式 → 啟動」把 Ollama 關掉,交給排程工作。

## 8. (可選)Workers AI 雲端備援

在沒有 GPU 的電腦上架站,或 GPU 電腦的 Ollama 暫時不能用時,可以讓**非敏感**文件改用 Cloudflare 上的 Gemma 4 26B。
**藥袋、沒選類型的文件、上傳時選「醫療與保險」「身分證明」的文件,以及初賽還不能自動判讀的文件(存摺、房地權狀、租約等)
仍然只在本機辨識**,不會送雲端;設定頁也關不掉這一條。

1. Cloudflare 儀表板 → **AI → Workers AI → Use REST API → Create a Workers AI API Token**。
   - 官方範本只有 **Workers AI Read** 與 **Workers AI Edit** 兩項權限:**不要再加別的權限**;
     Account Resources 只選這一個帳號;設定到期日(例如比賽結束後)。**不要用 Global API Key。**
2. 同一頁複製 **Account ID**。
3. 設成「使用者」環境變數(排程工作用同一個使用者身分執行,讀得到):

```powershell
[Environment]::SetEnvironmentVariable("CF_ACCOUNT_ID", "<Account ID>", "User")
[Environment]::SetEnvironmentVariable("CF_API_TOKEN", "<API Token>", "User")
```

4. 重新開機(或依第 10 節重新啟動排程工作):已經在跑的網頁讀不到剛設好的環境變數。
5. 到網頁的「設定」,把「辨識模式」改成「可以用雲端備援」(切換前會先跳確認框),按儲存。
   `/healthz` 會顯示 `"provider": "workers_ai"`,並列出雲端與本機兩個模型。
   - 也可以把 `config.yaml` 的 `model.provider` 改成 `workers_ai`;但**設定頁存過的辨識模式會蓋過 `config.yaml`**,
     存過之後就以設定頁為準。
   - 沒設好這兩個環境變數時,設定頁不能選「可以用雲端備援」。

- Token 只放在環境變數:不寫進 `config.yaml`、不放進 repo、不貼到聊天室。程式不會把 Token 寫進紀錄,`/healthz` 也不顯示。
- 懷疑外洩就到儀表板把 Token 換新(Roll)或刪除。

## 9. 上線驗收清單

驗收與展示一律用 `tools/make_demo_docs.py`、`tools/make_sample.py` 產生的**合成文件**,不要拍家裡真的帳單或藥袋。

- [ ] 手機用行動網路(不連家裡 Wi-Fi)開 `https://app.example.com` → 先出現 Cloudflare 登入頁 → 收 email 驗證碼登入。
- [ ] 不在名單上的 email 登不進去。
- [ ] 上傳一張合成帳單 → 看到結果頁;上傳合成藥袋(先選「醫療與保險」→「藥袋」)→ 到「家人確認」按「確認」。
- [ ] 開「設定」:「系統狀態」顯示模型連得上。
- [ ] 重新開機、**不要登入 Windows**,等 3 分鐘 → 手機重新整理還能用。
- [ ] 在 GPU 電腦開 `http://127.0.0.1:8000/healthz` → `"status": "ok"`。
- [ ] 用工作管理員結束 `python.exe` → 約 3 到 4 分鐘內自己恢復(`logs\service\watchdog.log` 有「重新啟動網頁」)。
- [ ] 電腦瀏覽器按 F12 → Network → 點首頁:回應標頭有 `content-security-policy`、`x-frame-options: DENY`、`cache-control: no-store`。
- [ ] 驗收做完、正式交給家人用之前,到「設定」→「刪除全部資料」清掉驗收時上傳的合成文件。

## 10. 更新到新版

在系統管理員 PowerShell、repo 資料夾:

```powershell
git pull
.venv\Scripts\python -m pip install -r requirements.txt
Stop-ScheduledTask -TaskName senior-doc-assistant
Start-ScheduledTask -TaskName senior-doc-assistant   # 重新啟動時會關掉舊的網頁與通道,換成新版
```

`/healthz` 的 `version` 會顯示新版的日期(發佈新版時改 `web/app.py` 的 `APP_VERSION`)。

## 11. 疑難排解

| 症狀 | 可能原因 | 處理 |
|---|---|---|
| 手機出現 Cloudflare 的 1033 錯誤頁 | 通道沒連上 | 看 `logs\service\cloudflared.err.log`;7844 埠被擋見第 4 節 |
| 手機出現 502 Bad Gateway | 通道通了,但網頁沒在跑 | GPU 電腦開 `/healthz` 打不開就看 `web.err.log`;監看腳本 3 分鐘內會自動重啟 |
| 頁面寫「這次的操作沒有送出」(錯誤代碼 403) | 頁面開太久、瀏覽器清掉或封鎖了 cookie | 回首頁重新操作一次;一直發生就確認瀏覽器沒有封鎖這個網站的 cookie |
| 閒置很久後按按鈕沒反應,或出現「這個網址不能這樣使用」 | Access 登入過期,送出的表單被導去登入頁 | 重新整理頁面、重新登入後再按一次;把 Access 的 Session duration 設長一點(第 5 節) |
| `/healthz` 一直是 `"ollama": "unreachable"` | Ollama 沒裝好或一直當掉 | 看 `ollama.err.log`;執行 `ollama list` 確認有 `gemma4:12b` |
| 設定頁不能選「可以用雲端備援」 | 這台沒設好 `CF_ACCOUNT_ID`、`CF_API_TOKEN`,或設好後網頁還沒重新啟動 | 依第 8 節設好環境變數,再重新開機或重新啟動排程工作(第 10 節) |
| 上傳後等很久才有結果 | 第一次要把模型載進顯示卡 | 第二張起會比較快;想讓模型常駐,把使用者環境變數 `OLLAMA_KEEP_ALIVE` 設成 `24h` 後重開機 |
| `Fatal error in launcher: Unable to create process` | 資料夾改過名,`.venv\Scripts\*.exe` 還記著舊路徑 | 一律用 `.venv\Scripts\python -m …`;還是不行就刪掉 `.venv` 重建 |
| PowerShell 說「這個系統上已停用指令碼執行」 | 執行原則擋住未簽章的腳本 | 照本文的寫法,在前面加 `powershell -NoProfile -ExecutionPolicy Bypass -File` |
| 開機後服務沒起來 | 排程工作沒跑或一啟動就失敗 | 工作排程器 → 工作排程器程式庫 → `senior-doc-assistant` 看「上次執行結果」;再看 `watchdog.log` |
| 上傳時說「檔案超過 15MB」 | 照片太大 | 改用手機相機直接拍(通常 2 到 6MB),或選較小的檔案 |

## 12. 不要做的事

- 不要把網頁或 Ollama 改成對所有網卡開放,也不要在路由器開 8000 或 11434 埠:會繞過 Access,任何人都能連。
- 不要在 Access 加 Bypass 或 Everyone 規則。
- 不要把 `config.yml`、`<Tunnel ID>.json`、Token、家人的 email 放進 repo、截圖或簡報。
- 不要用沒有 Access 的臨時通道開放真實資料(第 4 節)。
